# ADR-004：轻量质量门禁替代 SonarQube（首版）

- 状态：**提议（待阶段 0 确认）**
- 日期：2026-10-19
- 相关：`docs/phase-0/02-solution-design.md`

## 背景

课程第 5 章用 SonarQube + `waitForQualityGate` 做代码质量门禁，但需要 SonarQube + PostgreSQL（约 2–3 GB 内存）、特定内核参数、LDAP/令牌管理；本机当前 Docker Hub 不可达、arm64 镜像支持不确定，且项目只有一个 Go 服务。直接引入会显著增加环境风险，收益有限。

## 决策

首版使用**构建内质量门禁**，全部在推送镜像之前执行：

1. `gofmt -l` 无输出；
2. `go vet ./...` 无告警；
3. `go test -race ./...` 全绿；
4. 语句覆盖率 ≥ 60%（首版阈值，按实际测试逐步提高）；
5. 简单硬编码密钥扫描（正则），失败即阻断；
6. 测试报告转换 JUnit XML，Jenkins 归档；覆盖率 HTML 归档。

门禁失败 → 流水线终止，不构建/推送镜像、不更新 GitOps。

## 备选方案

| 方案 | 优点 | 不选原因 |
|---|---|---|
| SonarQube CE | 统一质量平台、规则多 | 内存/DB/镜像/arm64 风险；单项目收益低；课程配置含弱口令/LDAP |
| golangci-lint | Go 专用、规则丰富 | 需额外下载/版本管理；首版 vet/gofmt 已覆盖基础；可作为后续增强 |
| Trivy/govulncheck | 依赖/镜像漏洞 | 静态 scratch 镜像漏洞面小；需外网漏洞库；后续加入 |
| 仅测试 | 最简单 | 不能覆盖格式/静态问题；不构成门禁 |

## 影响

- 正面：零额外服务、快速、可复现；门禁在正确位置阻断。
- 负面：规则少于 SonarQube；没有统一的质量历史/技术债视图；覆盖率阈值需要维护。
- 迁移：若引入 SonarQube，保留现有测试/覆盖率作为前置门禁，Sonar 作为第二道门禁；质量门禁配置入仓，令牌按项目/期限管理。

## 验证要求

- 失败样例（格式/断言/覆盖率）确实在 Push 前失败。
- 覆盖率报告与 JUnit 可下载。
- 阈值调整有记录，不通过降低阈值来「修复」失败。
