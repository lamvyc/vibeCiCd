# ADR-005：暂缓工具清单与重新评估条件

- 状态：**提议（待阶段 0 确认）**
- 日期：2026-10-19
- 相关：`docs/phase-0/02-solution-design.md`

## 决策

以下工具首版**不运行**，只保留在课程对照/后续路线中。每项都给出重新评估的触发条件，避免「为了覆盖课程目录而堆工具」。

| 工具 | 课程位置 | 暂缓理由 | 重新评估条件 |
|---|---|---|---|
| SonarQube | 5-3~5-6 | 内存 2–3 GB；DB/LDAP；arm64/网络不确定；轻量门禁已覆盖 | 有稳定镜像与内存；需要统一质量平台/技术债视图 |
| Argo Rollouts | 10-14~10-22 | 无渐进发布需求；蓝绿/金丝雀需多副本/流量；课程两节缺失 | GitOps 稳定；需要金丝雀/蓝绿；有 Istio 或足够副本 |
| Istio + 分析模板 | 10-19~10-22 | 1.5–2 GB；单机收益低；无真实流量比例 | 需要按流量灰度/自动回滚；资源充足 |
| Tekton | 第 6 章 | 与 Jenkins 职责重复；`v1beta1` 过时；需 K8s 控制器 | 团队决定 K8s 原生 CI；有迁移预算 |
| Drone | 第 7 章 | 维护态；GitLab 子组限制；配置不安全 | 仅作对比，不建议引入 |
| KubeVela | 第 8 章 | 栈重；多集群未真验；命令缺失 | 需要 OAM/多集群交付；有真实多集群 |
| Zadig | 第 9 章 | 版本过时；MySQL+Mongo+NFS 栈重；社区版门禁弱 | 需要一体化平台且资源充足 |
| OpenLDAP | 3-6、5-4 等 | 单用户本地；增加认证依赖 | 多用户/SSO 需求 |
| MeterSphere | 5-7~5-9 | 平台重；接口探针已覆盖关键路径 | 需要完整 API 测试管理 |
| 飞书通知 | 5-2 | 外部 webhook/凭据；本地失败报告已足够 | 有团队通知渠道与合规要求 |
| NFS/多节点 | 3-4/3-5 | 单机无 NFS；local-path/无 PVC 足够 | 多节点/共享存储需求 |
| Grafana/Alertmanager | 10-19 | 增加组件；Prometheus UI + 规则已能验证 | 需要可视化/告警路由 |

## 影响

- 正面：降低环境失败面；每个工具都有明确职责；项目更易运行与维护。
- 负面：课程覆盖度不完整；部分能力（灰度、SSO、统一质量平台）暂缺。
- 补足：文档明确「未实现/受环境限制」及迁移条件，不把暂缓写成已完成。

## 验证要求

- 最终验收表按实际实现标注状态，不用「课程有」推断「项目有」。
- 若重新引入任一工具，新增 ADR 记录原因、版本、资源、权限与回退方案。
